## 二、Git 全局身份配置

提交记录中的作者信息由全局配置决定，先完成配置：

```console
$ git config --global user.name "liaozhe789"
$ git config --global user.email "266676191+liaozhe789@users.noreply.github.com"
$ git config --global init.defaultBranch main
$ git config --global core.autocrlf true

$ git config --global --list | grep -E "user\.|init\.|autocrlf"
user.name=liaozhe789
user.email=266676191+liaozhe789@users.noreply.github.com
init.defaultbranch=main
core.autocrlf=true
```

邮箱采用 GitHub 提供的 noreply 地址，既能把提交归属到账号，又不会在公开仓库中暴露真实邮箱。`core.autocrlf=true` 用于处理 Windows 与 Linux 换行符差异。

## 三、SSH 认证

### 3.1 遇到的问题

首次执行 `ssh -T git@github.com` 时认证失败：

```console
$ ssh -T git@github.com
Host key verification failed.
```

### 3.2 原因分析

`~/.ssh/config` 中将 `github.com` 重定向到了 443 端口：

```
Host github.com
  HostName ssh.github.com
  Port 443
  User git
  IdentityFile C:\Users\qiyong\.ssh\id_ed25519_cram
  IdentitiesOnly yes
```

这是校园网环境下绕过 22 端口封锁的常规做法，但 `known_hosts` 中只记录了 `github.com`，没有记录 `[ssh.github.com]:443`，主机密钥校验因此无法通过。

### 3.3 处理过程

先取回主机密钥并核对指纹，确认与 GitHub 官方公布值一致后再写入 `known_hosts`：

```console
$ ssh-keyscan -p 443 ssh.github.com > gh_keys.txt
$ ssh-keygen -lf gh_keys.txt
256 SHA256:p2QAMXNIC1TJYWeIOttrVc98/R1BUFWu3/LiyKgUfQM [ssh.github.com]:443 (ECDSA)
3072 SHA256:uNiVztksCsDhcc0u9e8BujQXVUpKZIDTMczCvj3tD2s [ssh.github.com]:443 (RSA)
256 SHA256:+DiY3wvvV6TuJJhbpZisF/zLDA0zPMSvHdkr4UvCOqU [ssh.github.com]:443 (ED25519)
```

| 密钥类型 | 计算所得指纹 | 与官方公布值比对 |
| --- | --- | --- |
| RSA | `uNiVztksCsDhcc0u9e8BujQXVUpKZIDTMczCvj3tD2s` | 一致 |
| ED25519 | `+DiY3wvvV6TuJJhbpZisF/zLDA0zPMSvHdkr4UvCOqU` | 一致 |
| ECDSA | `p2QAMXNIC1TJYWeIOttrVc98/R1BUFWu3/LiyKgUfQM` | 一致 |

指纹一致说明取回的确实是 GitHub 的密钥，不存在中间人风险，可以写入：

```console
$ cat gh_keys.txt >> ~/.ssh/known_hosts
$ ssh -T git@github.com
Hi liaozhe789! You've successfully authenticated, but GitHub does not provide shell access.
```

返回信息中的账号名与 GitHub 账号一致，认证打通。

## 四、仓库创建与首次推送

远程仓库 `se-lab` 在 GitHub 网页端创建为空仓库，未勾选初始化 README，避免首次推送产生无关的合并记录。本地克隆后建立目录结构并提交：

```console
$ git clone git@github.com:liaozhe789/se-lab.git
Cloning into 'se-lab'...
warning: You appear to have cloned an empty repository.

$ git add -A
$ git commit -m "docs: 初始化仓库结构与实验一说明"
[main 3e16504] docs: 初始化仓库结构与实验一说明

$ git push -u origin main
To github.com:liaozhe789/se-lab.git
 * [new branch]      main -> main
branch 'main' set up to track 'origin/main'.
```

## 五、分支管理

按仓库约定，`main` 只接受通过 Pull Request 合入的改动，日常开发在 `dev` 上进行：

```console
$ git checkout -b dev
$ git push -u origin dev
 * [new branch]      dev -> dev

$ git branch -a
* dev
  main
  remotes/origin/dev
  remotes/origin/main
```

## 六、协作流程演练

完整流程为：Issue 登记任务 → 从 `dev` 切出功能分支 → 提交并推送 → 发起 Pull Request 关联 Issue → 评审合并。

本记录本身即按该流程提交：任务登记在 Issue #1，改动位于 `feature/env-record` 分支，通过 Pull Request 合入 `dev`。
