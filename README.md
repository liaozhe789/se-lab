## 目录约定

每个实验单独占一个目录，目录内按用途划分子目录：

- `src/`：源代码
- `docs/`：实验过程中的设计文档、说明
- `screenshots/`：运行与操作截图

## 提交规范

提交信息采用 `<类型>: <说明>` 的形式，类型取值如下：

| 类型 | 含义 |
| --- | --- |
| `feat` | 新增功能 |
| `fix` | 修复缺陷 |
| `docs` | 文档变更 |
| `refactor` | 重构，不改变外部行为 |
| `chore` | 构建、配置等杂项 |

## 分支约定

- `main`：稳定分支，只接受通过 Pull Request 合入的改动
- `dev`：日常开发分支
- `feature/<名称>`：单个功能的开发分支

## 协作流程

1. 在 Issues 中登记任务，说明背景与验收标准
2. 从 `dev` 切出 `feature/<名称>` 分支开发
3. 完成后推送分支，发起 Pull Request 并关联对应 Issue
4. 评审通过后合并回 `dev`，由 `dev` 定期合入 `main`
